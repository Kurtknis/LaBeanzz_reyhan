## Phase 6: orders
- **Order creation:** `POST /orders` makes one order per supplier, shares a `group_id` across them, and snapshots prices. The server computes the total and ignores any price or owner id in the request. `POST /blends/:id/reorder` splits a total quantity by recipe percentage.
- **Stock:** reserving takes row locks. Two owners racing for 60 kg each of a 100 kg bean produces exactly one 201 and one 409. Cancelling releases stock, and beans flip to `LOW_STOCK` or `OUT_OF_STOCK` as needed.
- **Status moves:** the supplier moves an order one step forward. The owner can cancel only while it is pending or confirmed, and mark it completed after delivery. Any other move returns 409, and delivery adds to the owner's stock.
- **Who sees what:** other users get 404. Suppliers see no blend data.
- **UI:** orders list and detail, a five-segment timeline (label "Blending" for `PREPARING`), a supplier fulfilment page, and order forms on bean and blend pages.

## Existing bugs I fixed along the way
These blocked Phase 6 and 7, or were found while verifying them.
- **Blend and bean detail pages returned 500.** Server components called the API without the user's cookies, so the app redirected them to login. List pages hid it behind empty states. `client.ts` now forwards cookies. This is the one fix that touches your earlier pages, so look at it first.
- **Fresh installs could not start:**
  - `flask-limiter==3.9.4` doesn't exist on PyPI. It is now `3.12`.
  - `requests` had been dropped but `google_auth.py` still needs it.
  - A plain `postgresql://` URL fails under SQLAlchemy 2.1, because it looks for `psycopg` v3. The config and `migrations/env.py` now name `psycopg2`.
- **A bad recipe returned 500 instead of 422.** Pydantic error context couldn't be serialized.
- **Provider errors leaked to the browser.** Upstream text such as `OpenRouter returned 401…` reached users. It now returns a generic 503, and the detail stays in `ai_generations`.
- **Transport failures became 500s.** They included a blank API key or a timeout. They also broke feedback submission whenever embeddings were unreachable. All provider failures are now handled in `ai_service`.
- **Deleting a bean that blends or orders use** returned an unhandled error. It now returns a 409.
